# 成都周边骑行路线小红书发布工具需求方案

## 1. 项目概述

本项目构建一个本地 Web 应用，用于生成并辅助发布成都周边骑行路线的小红书帖子。用户录入路线信息后，系统使用 AI 生成种草型小红书文案和类似 Strava 风格的封面海报，并通过浏览器自动化辅助填写小红书桌面端发布页面。最终发布动作由用户人工确认。

系统重点解决三件事：

- 降低骑行路线内容创作成本。
- 保证里程、爬升、难度、起终点等路线事实信息准确。
- 提高小红书发布效率，同时保留人工审核和最终发布控制。

## 2. 产品范围

第一版产品范围包括：

- 本地 Vue Web 前台。
- Node.js 后端服务。
- 手动录入成都周边骑行路线信息。
- 使用 OpenAI Responses API 生成结构化小红书文案。
- 使用图片生成 API 生成类似 Strava 风格的封面海报背景。
- 本地程序叠加封面海报中的路线事实信息。
- 将生成后的内容保存为 Markdown。
- 使用 Playwright 辅助打开并填写小红书桌面端发布页面。

第一版不包括：

- 全自动发布。
- 手机端发布自动化。
- GPX 导入。
- 用户上传自己的骑行实拍图。
- 独立路线信息卡片图。
- 路线规划或导航。
- 社交账号管理。
- 多账号发布。
- 定时发布。
- 数据分析或互动表现追踪。
- 实时路况验证。

## 3. 用户流程

1. 用户打开本地 Web 应用。
2. 用户在表单中录入路线信息。
3. 用户点击“AI 生成”。
4. 系统生成小红书标题、正文、话题标签、封面标题、封面副标题和图片提示词。
5. 用户在页面中预览并编辑生成内容。
6. 用户点击“生成封面海报”。
7. 系统生成封面海报背景图。
8. 系统在封面海报上叠加路线名称、里程、爬升、难度、起终点等事实信息。
9. 用户保存最终内容，系统生成 Markdown 文件。
10. 用户点击“辅助发布”。
11. 系统使用 Playwright 打开小红书桌面端发布页面。
12. 系统上传封面海报，并填写标题、正文和话题标签。
13. 用户人工完成登录、验证码、内容检查和最终发布。

## 4. 路线录入字段

### 4.1 必填字段

- 路线名称
- 起点
- 终点或折返点
- 总里程，单位公里
- 累计爬升，单位米
- 难度
- 路况类型
- 路线亮点
- 风险提醒和安全注意事项
- 补给点

### 4.2 推荐字段

- 推荐季节
- 推荐出发时间
- 适合人群
- 交通建议
- 预计耗时
- 拍照点
- 美食推荐

### 4.3 可选字段

- 用户指定话题标签
- 其他补充说明

## 5. AI 文案生成

系统根据用户录入的结构化路线事实生成种草型小红书内容。AI 输出采用结构化 JSON，便于前端渲染、校验和编辑。

生成内容包括：

- 3 个标题候选
- 1 篇种草型帖子正文
- 路线攻略信息
- 路线彩蛋内容
- 话题标签
- 封面主标题
- 封面副标题
- 图片生成提示词

文案生成要求：

- 保留用户录入的路线事实，不擅自修改里程、爬升、起终点和风险提醒。
- 风格偏种草，但不夸大路线安全性、难度适配或风景体验。
- 攻略信息应覆盖适合人群、出发时间、补给点、拍照点、交通建议和注意事项。
- 彩蛋内容应提供路线中的特别体验，例如隐藏拍照点、适合停留的咖啡店、风景转角、季节限定景观或返程小吃。
- 彩蛋内容必须基于用户输入，或以“可探索”“可留意”的方式表达，不能编造确定存在的店铺、景点或服务。
- 正文适合直接发布到小红书。
- 标签围绕成都骑行、成都周边游、公路车、周末骑行、路线攻略等主题生成。

## 6. 封面海报生成

系统生成适合小红书竖图发布的攻略海报封面。视觉风格参考 Strava 的运动数据感和户外骑行氛围，突出速度感、路线感和数据感。

封面海报由两部分组成：

- AI 生成的视觉背景。
- 本地程序叠加的路线事实信息。

AI 生成背景应体现成都周边骑行氛围，例如：

- 山路
- 绿道
- 河谷
- 田园
- 周末骑行
- 户外运动数据视觉
- 路线轨迹或地图纹理氛围

本地叠加信息包括：

- 路线名称
- 总里程
- 累计爬升
- 难度
- 起点和终点

图片模型不负责生成最终中文文字和关键数字，避免出现错字、乱码或错误数据。

## 7. Markdown 保存

系统将最终确认后的生成内容保存为 Markdown 文件。Markdown 应包含：

- 路线基础信息
- 选定标题
- 帖子正文
- 路线攻略信息
- 路线彩蛋内容
- 话题标签
- 封面主标题
- 封面副标题
- 图片生成提示词
- 封面海报文件路径
- 生成时间

Markdown 用于内容归档、二次编辑和后续复用。

## 8. 发布辅助

系统通过 Playwright 辅助小红书桌面网页端发布。

发布辅助能力包括：

- 打开小红书发布入口。
- 上传生成的封面海报。
- 填入选定标题。
- 填入帖子正文。
- 填入话题标签。
- 停留在最终发布前的检查状态。

系统不执行以下行为：

- 绕过登录或验证码。
- 存储小红书账号密码。
- 自动点击最终发布按钮。
- 规避平台限流、风控或反滥用机制。

## 9. 技术组成

### 9.1 前端

前端使用 Vue 构建本地 Web UI，提供：

- 路线录入表单
- AI 生成按钮
- 文案预览和编辑
- 封面海报预览
- Markdown 保存按钮
- 辅助发布按钮
- 错误提示和加载状态

### 9.2 后端

后端使用 Node.js，提供本地 API 服务，负责：

- 校验路线输入
- 调用 OpenAI Responses API
- 调用图片生成 API
- 合成封面海报
- 保存 Markdown 文件
- 管理 Playwright 发布辅助流程

### 9.3 后端 API

- `POST /api/generate-post`：生成小红书文案和图片提示词。
- `POST /api/generate-cover`：生成封面海报背景并叠加路线事实信息。
- `POST /api/save-markdown`：保存最终内容为 Markdown 文件。
- `POST /api/assist-publish`：启动小红书发布辅助流程。

## 10. 风险控制

- 最终发布必须由用户人工确认。
- 小红书账号登录和验证码由用户自行处理。
- 应用不保存小红书账号密码。
- AI 生成内容必须允许用户编辑后再发布。
- 关键路线事实由用户输入和本地渲染控制。
- 图片中文字和数字由本地程序叠加，不交给图片模型生成。
- 图片生成通过显式按钮触发，避免自动重复消耗 API 成本。
- 浏览器自动化范围仅限打开页面、上传图片和填写表单。

## 11. 验收标准

- 用户可以通过本地 Web 表单录入完整路线。
- 系统可以基于路线数据生成结构化种草型小红书文案，并包含攻略和彩蛋内容。
- 用户可以预览和编辑生成文案。
- 系统可以生成类似 Strava 风格的封面海报。
- 封面海报中的路线事实信息准确，并由本地程序渲染。
- 用户可以将生成后的内容保存为 Markdown。
- 用户可以从应用启动小红书辅助发布流程。
- 在小红书页面结构允许的情况下，系统可以填入标题、正文、标签并上传封面海报。
- 系统不会自动点击最终发布按钮。
