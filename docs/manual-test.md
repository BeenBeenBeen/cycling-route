# 手动验证清单

## 1. 启动

1. 确认 `.env` 已配置。
2. 执行：

```bash
npm run dev
```

3. 打开：

```text
http://127.0.0.1:5173
```

4. 页面显示“成都骑行路线发布工具”。

## 2. 路线录入

填写测试路线：

| 字段 | 值 |
|---|---|
| 路线名称 | 成都到青城山周末骑行 |
| 起点 | 犀浦 |
| 终点或折返点 | 青城山 |
| 总里程 | 82 |
| 累计爬升 | 620 |
| 难度 | 进阶 |
| 路况类型 | 绿道、公路、乡道 |
| 路线亮点 | 绿道舒服、青城山适合拍照 |
| 风险提醒 | 返程注意车流 |
| 补给点 | 都江堰城区 |

## 3. 生成文案

1. 点击“AI 生成”。
2. 成功后确认：
   - 标题候选出现 3 个选项。
   - 正文、攻略、彩蛋、话题标签可编辑。
   - 封面标题、封面副标题、图片提示词可编辑。
3. 如果没有 OpenAI key 或额度不足，页面显示清晰错误，终端输出 JSON Lines 日志。

## 4. 生成封面

1. 点击“生成封面海报”。
2. 成功后确认：
   - 页面显示 `coverPath`。
   - `data/images/` 下有背景图和封面图。
   - 封面图包含路线事实，不依赖图片模型生成最终中文文字。

## 5. 保存 Markdown

1. 点击“保存 Markdown”。
2. 成功后确认：
   - 页面显示 `markdownPath`。
   - `data/posts/` 下生成 Markdown 文件。
   - 文件包含选定标题、路线信息、正文、攻略、彩蛋、话题标签、封面信息和生成时间。
3. 在同一分钟内重复保存同一路线，确认不会覆盖旧文件，会生成带序号的新文件。

## 6. 辅助发布

1. 确认已有生成内容和 `coverPath`。
2. 点击“辅助发布”。
3. 浏览器打开小红书发布页。
4. 确认封面、标题、正文和标签已填入。
5. 确认系统停在最终发布前，未自动点击发布按钮。

## 7. 日志

当 `.env` 中设置：

```env
LOG_LEVEL=debug
```

终端应输出：

- API 请求开始和完成日志。
- API 请求头和请求 body。
- OpenAI 请求头和请求 body。
- 错误时包含错误名称和消息。

日志应脱敏 API key、authorization、cookie、token、secret、验证码和图片 base64。

## 8. 回归验证

执行：

```bash
npm test
npm run build
```

确认全部通过。
