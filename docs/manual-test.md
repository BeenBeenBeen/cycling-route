# 手动验证清单

## 1. 启动

1. 确认 `.env` 已配置。
2. 执行：

```bash
npm run dev
```

3. 打开：

```text
http://127.0.0.1:5173
```

4. 页面显示“成都骑行路线发布工具”。

## 2. V2.0 路线生成

1. 在“路线规划”中输入：
   - 起点：`犀浦`
   - 终点：`青城山`
2. 点击“查询候选地点”。
3. 确认页面展示起点和终点候选。
4. 分别选择一个起点候选和一个终点候选。
5. 点击“生成骑行路线”。
6. 成功后确认：
   - “路线地图”显示路线名称、里程、累计爬升。
   - 下方路线表单自动填入路线名称、起点、终点、总里程、累计爬升和预计耗时。
   - 终端日志包含 `route.place.search.*`、`route.plan.*`、`elevation.lookup.*`。

如果 Open-Elevation 失败，页面仍应保留路线结果，并显示可排查的错误信息；累计爬升需要人工确认。

## 3. 生成 GPX 路书

1. 确认已生成骑行路线。
2. 点击“生成 GPX 路书”。
3. 成功后确认：
   - 页面显示 `gpxPath`。
   - 下载链接为 `/media/routes/*.gpx`。
   - `data/routes/` 下生成 `.gpx` 文件。
   - GPX 文件中的坐标为 WGS84，包含 `<trkpt>`；海拔成功时包含 `<ele>`。
4. 将 GPX 文件导入 Strava，确认 Strava 能识别路线。

## 4. 路线录入

填写测试路线：

| 字段 | 值 |
|---|---|
| 路线名称 | 成都到青城山周末骑行 |
| 起点 | 犀浦 |
| 终点或折返点 | 青城山 |
| 总里程 | 82 |
| 累计爬升 | 620 |
| 难度 | 进阶 |
| 路况类型 | 绿道、公路、乡道 |
| 路线亮点 | 绿道舒服、青城山适合拍照 |
| 风险提醒 | 返程注意车流 |
| 补给点 | 都江堰城区 |

如果已经通过 V2.0 生成路线，以上字段会被自动填充，仍可手工修改。

## 5. 生成文案

1. 点击“AI 生成”。
2. 成功后确认：
   - 标题候选出现 3 个选项。
   - 正文、攻略、彩蛋、话题标签可编辑。
   - 封面标题、封面副标题、图片提示词可编辑。
3. 如果没有 OpenAI key 或额度不足，页面显示清晰错误，终端输出 JSON Lines 日志。

## 6. 生成封面

1. 点击“生成封面海报”。
2. 成功后确认：
   - 页面显示 `coverPath`。
   - `data/images/` 下有背景图和封面图。
   - 封面图包含路线事实，不依赖图片模型生成最终中文文字。

## 7. 保存 Markdown

1. 点击“保存 Markdown”。
2. 成功后确认：
   - 页面显示 `markdownPath`。
   - `data/posts/` 下生成 Markdown 文件。
   - 文件包含选定标题、路线信息、正文、攻略、彩蛋、话题标签、封面信息和生成时间。
   - 如果已生成 GPX，文件包含“GPX 路书”和 `data/routes/*.gpx` 路径。
3. 在同一分钟内重复保存同一路线，确认不会覆盖旧文件，会生成带序号的新文件。

## 8. 辅助发布

1. 确认已有生成内容和 `coverPath`。
2. 点击“辅助发布”。
3. 浏览器打开小红书发布页。
4. 确认封面、标题、正文和标签已填入。
5. 确认系统停在最终发布前，未自动点击发布按钮。

## 9. 日志

当 `.env` 中设置：

```env
LOG_LEVEL=debug
```

终端应输出：

- API 请求开始和完成日志。
- API 请求头和请求 body。
- OpenAI 请求头和请求 body。
- 高德路线和地点搜索调用日志。
- Open-Elevation 批量查询日志。
- GPX 保存日志。
- 错误时包含错误名称和消息。

日志应脱敏 API key、authorization、cookie、token、secret、验证码和图片 base64。

## 10. 常见故障

| 问题 | 处理 |
|---|---|
| 缺少 `AMAP_API_KEY` | 检查 `.env`，填写高德 Web Service key 后重启服务 |
| 高德无候选地点 | 换更具体的地点名，或增加城市限定 |
| 高德路线失败 | 检查 key 权限、额度、起终点坐标和终端 `route.plan.failed` 日志 |
| Open-Elevation 失败 | 可先人工填写累计爬升；检查 `OPEN_ELEVATION_BASE_URL` 和网络 |
| GPX 下载 404 | 确认 `data/routes/` 下存在对应 `.gpx` 文件 |
| DuckCoding hard limit | 调整上游额度、充值或更换可用 key |

## 11. 回归验证

执行：

```bash
npm test
npm run build
```

确认全部通过。
